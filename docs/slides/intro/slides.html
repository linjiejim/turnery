一句话立住 Turnery 是什么：给 coding agent 用的参数化 CAD。

  • 右边这个外壳是 agent 用一句话需求建出来的，后面会拆开讲。
  • 关键词是「看得懂、核得准、改得动」，整场就讲这三件事。

先说清楚分工。

分工

agent 来建，
内核来核对，
你来定方向。

最短的说法，先让人记住。

  • agent 负责动手；数字对不对由几何内核量，不由 agent 自己说；方向由人定。
  • 不要说成「AI CAD 软件」，会被拿去和 Fusion 比功能。

为什么要这样分？看看今天让模型做零件会拿到什么。

一个小改动

说「壁厚改成 3 mm」时，会发生什么

网格没有可改的东西。重新生成一遍，祈祷其他地方别变。一句话生成 3D
脚本能改，前提是你读得懂代码、它还能跑。没人告诉你孔还在不在原处。OpenSCAD · CadQuery
Turnery 特征树把 t 从 2 改成 3，引用它的地方都跟着变；「壁厚 2」这项核对立刻变红。feature tree

用一个具体的小改动对比三条路线。

  • 网格路线：没有参数，只能重来。
  • 脚本路线：对会读代码的人很好，但改完没人帮你核对。
  • 特征树：改一个数，相关的都跟着变，而且原来的要求还在、会被重新量。

第一点：交出来的到底是什么。

交付物

交出来的是一棵特征树

命名的参数、按顺序排的特征，每一步写着它为什么存在。一个 JSON 文件：能 diff，能进 git，一个月后打开还能改。

把 H 从 28 改成 40，螺丝柱自己长到 36 mm。

{
  "id": "posts",
  "name": "螺丝柱",
  "intent": "柱子从内底一直长到内顶：分型后下半段装热熔螺母，上半段让螺钉穿过。改总高时柱子跟着变",
  "op": "extrude",
  "sketch": "sk_posts",
  "until": "next"
}

examples/sensor-enclosure/enclosure.turnery.json 里的一个特征

第一个要讲清的点：交付物是特征树，不是网格，也不是一段脚本。

  • 指着 until: "next"：它写的是「长到下一个面为止」，不是「24 mm」，所以改总高时柱子自己跟着长。
  • intent 是写给人看的：一个月后你还知道这一步为什么在这里。
  • 现场可以演示：打开这个文件，把 H 改成 40。

这棵树是怎么来的？一句话需求。

一个例子

一句话需求，15 次工具调用

「80×50×28，2 mm 壁厚，R6 圆角，分成底座和盖，四颗 M3 沉头螺丝配热熔螺母，前壁开 USB-C，盖上五条散热槽。」

Tool calls15每一步都经过校验
Params11t、H、圆角……都有名字
Features17每个都写着意图
Checks5每次重建都重新量

用示例项目的真实数字说明规模。

  • 这些数字都在 examples/sensor-enclosure 里，可以当场打开对。
  • agent 只能通过带 schema 的工具改这棵树，失败的特征会带着原因和建议回来。

一步一步长出来的样子。

回放

一步一个特征

时间线可以按特征回放整个建模过程。

让人直观看到「特征」是什么。

  • 每一格是一个特征之后的状态；窗口里的时间线就是按这个顺序回放。

第二点：建完了，怎么知道它对不对？

要求留在文件里

做没做到，
由内核量

「80×50×28、2 mm 壁、四个 M3 孔」变成核对项，每次改动后内核重新量一遍。

✓size80 × 50 × 2880 × 50 × 28 ✕wall2 mm3 mm ✓inserts4 × M3 热熔螺母4 × ⌀4 ✓screws4 × M3 沉头过孔4 × ⌀3.4 ✓seat盖子贴合底座0 mm

第二个要讲清的点：数字由内核量，不由 agent 自己说。

  • 演示：把 t 改成 3，「壁厚 2」立刻变红：要求 2 mm，实际 3 mm。
  • 不开窗口也能跑：turnery check 零件 --no-app，可以放进 CI。
  • 被问「LLM 空间能力差」时，就指这一页：所以才要内核来量。

第三点：说不清的时候怎么办？

双向

说不清的地方，
指给它看

点前壁，写「这里开 USB-C 口，离底 6 mm」。agent 下一次调用就读到这条备注，连同那个面和坐标。

反过来，它拿不准是哪个面时，会请你点一下。

第三个要讲清的点：人和 agent 之间可以指着说。

  • 备注钉在面上：agent 收到的是这个面、它来自哪个特征，以及你写的话。
  • request_pick：agent 主动请你点一个面。
  • 选择器按意思写（顶面、外环的边），每次重建重新解析，没有会过期的面编号。

还有一件常被问的事：模型从哪来？

你的 agent，你的订阅

接上 Claude Code 或 Codex，
Turnery 不调用任何模型。

不需要 API key。没有 agent 也行：内置助手用你自己选的模型和 key，key 留在你的电脑上。

打消「又要一个订阅」的顾虑。

  • 内置助手支持 DeepSeek、OpenRouter、Anthropic、OpenAI、Gemini、Kimi、智谱、通义、Ollama 等。
  • 它只能调 Turnery 的建模命令，碰不到别的文件。

把这些设计选择放在一起看。

为什么可靠

背后的四个设计选择

01 · schema

工具，不是生成代码

agent 只能通过校验过的工具改树。失败会带着原因和修法回来。

02 · selector

按意思选面

「顶面、只要外环的边」，每次重建重新解析，不存面编号。

03 · look / measure

agent 能看、能量

渲染视图和剖面，距离由内核返回，不靠它自己算。

04 · check

要求存下来

尺寸、壁厚、孔、间隙，每次改动后重新核对。

把前面三点背后的机制归拢成四条。

  • 「拓扑命名问题怎么办」：第二条就是答案，解析结果数量不对会报错并列出候选。
  • 「为什么不直接写 build123d」：第一条，每一步有名字和意图，人能点着改；需要代码时可以导出 build123d。
