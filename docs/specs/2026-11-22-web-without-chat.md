# 网页去掉对话建模，补上手动建特征

- 状态：已实现（2026-11-22，待合并）；和方案不同的地方见文末「落地记录」
- 日期：2026-11-22
- 范围：
  1. 工作台（网页和桌面版共用的组件）能不靠 AI 新建、编辑、调整特征的顺序：表单式的草图、拉伸、旋转、放样、孔、圆角、倒角、抽壳、拔模、阵列、镜像，改动实时重建；
  2. 网页去掉对话建模（「边做边学」和「直接做」）、分享链接和整个后端（`app/server`）；
  3. 练习卡搬到右侧面板，加「看参考做法」；
  4. 部署、文档、首页文案跟着改；服务器上的清理写成脚本交给 Jim。
- 不在范围：
  - 旧的分享链接（Jim：不管，直接失效）；
  - 草图约束、自由画线、在模型上拖手柄改尺寸、拖动排序；扫掠、筋、螺纹、拆件、导入的表单（这些特征照常能看、能改尺寸，只是没有「编辑」表单）；
  - 「看 agent 建一遍」的录制回放、新的互动课；
  - 桌面版的签名公证（要 Apple 开发者账号）和 Windows 版；
  - 桌面版的内置助手和 MCP：它们用的工具、系统提示词（`tools.ts`、`apply.ts`、`prompt.ts` 的 `systemPrompt`、`trim.ts`）都留着。
- 相关：`docs/specs/2026-11-06-studio-hand-modeling.md`（暂缓的手动建模方案，这次按它的思路做了一部分）、`docs/specs/2026-11-22-web-desktop-parity.md`、`app/src/studio/ui/step-panel.tsx`、`app/src/studio/ui/tree-overlay.tsx`、`app/src/studio/use-reselect.ts`、`app/src/desktop/core/engine.ts`

## 为什么

- 网页对话要养一个后端、两套助手、限流、每日预算和一个公开的模型 key。产品的主张是「用你自己的 agent」，网站上的公共额度和它不一致。
- 去掉对话以后，工作台里的人只能改已有特征的尺寸和选择，不能新建，也不能调顺序：8 个课后练习几乎都要加特征，「把盒子的特征顺序改对」要调顺序。所以手动建特征必须和去掉对话一起上线。
- 手动建特征做在网页和桌面版共用的组件里：桌面版没接 agent 时也能自己建，接了 agent 时人能直接补一步、改一步，不用每次都留备注。

## 已定

| 问题 | 决定 | 理由 |
| --- | --- | --- |
| D1 分享链接 | 去掉，旧链接不迁移，`/studio/s/:id` 落到 404 | Jim 2026-11-22 定的 |
| D2 草图 | 只做表单式：矩形、圆、正多边形、槽、文字、折线（点表），每个图形可以「挖掉」 | Jim 同意；自由画线和约束会变成做一个更差的 Onshape |
| D3 学习时问「为什么」 | 不再有 AI 回答，用练习的提示和「看参考做法」代替 | Jim 同意 |
| D4 实时预览 | 表单一变（防抖 300 ms），特征就写进特征树并重建；同一次编辑的所有改动合成一步撤销。「完成」关闭表单，「取消」撤销这一步 | 预览和最终结果是同一次重建，不会不一致；引擎和内核的前缀缓存都是现成的。没选「先在单独的通道预览，点应用才写进去」：引擎要多一套不落盘的重建，桌面版要多一条显示通道。代价：编辑中途的特征已经写进文件，桌面版的 agent 可能看到半成品 |
| D5 必填项没齐 | 不写进特征树，表单上写还差什么（「先在模型上选边」）；齐了才第一次写入 | 半成品不会让后面的特征报错 |
| D6 合成一步撤销 | 引擎的 `set_tree` 收一个可选的 `group`：撤销栈顶是同一个 `group` 时只换成新的树，不再压一条 | 改动最小；撤销回到打开表单之前的样子 |
| D7 插在哪 | 时间线回滚到某一步时，插在这一步后面；否则插在最后（文字特征之前，沿用 `applyEdit` 的规则） | 和专业软件的回滚棒一致，也是回滚这节课的教学点 |
| D8 调顺序 | 步骤面板里「上移一步」「下移一步」（引擎的 `move_feature`，不能排到它用到的特征前面）。不做拖动 | 练习的提示本来就写「上移一步」；按钮能用键盘 |
| D9 编辑已有特征 | 步骤面板加「编辑」，打开同一张表单；表单不认识的字段原样保留。没有表单的特征（扫掠等）不显示「编辑」 | agent 建的特征也能改，不会丢字段 |
| D10 网页视口 | 去掉标注（没有可以发给的对象），点击就是查看与选择，和桌面版默认一样 | 标注只为了发给助教 |
| D11 评测 | 保留 `npm run eval:studio`：模型路由和计价从 `server/` 搬到 `scripts/eval-models.ts`。它评的是桌面版内置助手也在用的系统提示词和工具 | 改提示词时还要有回归手段 |
| D12 浏览器里的旧数据 | 打开工作台时删掉自己填的 DeepSeek key、对话记录、对话模式、分享的删除口令 | key 是秘密，不该留在一个不再用它的网站上 |
| D14 取消 | 「取消」把这个特征写回打开表单之前的样子（新建的就删掉），用同一个 `group`。中间没有别的改动时，引擎发现这一组改回了原样，撤销栈和活动里都不留这一步；中间有 agent 的改动时，那次改动留着，取消算单独一步 | 审查时发现：只撤销栈顶，在中间插进别的改动后会只撤掉一半、新特征留在树里。补充 D4、D6（D6 的合并条件改成「这一组上次写下的树还是当前的树」，备注不再把一张表单拆成两步） |
| D15 拉伸、旋转要新草图 | 「＋」里的拉伸、旋转、拉伸切除要求有一个还没被用过的草图，否则写「先画一个新草图」 | 缺省值拿已用过的草图再拉一次，多半得到重叠或切掉整个实体；先草图后特征也正是课上的顺序 |
| D13 服务器 | 部署流程不再上传、重启 API；Caddy 的 `/api/*`、pm2 进程 `turnery-api` 和它的数据由 `app/scripts/retire-api.sh` 清理，Jim 运行；托管 key 由 Jim 到 OpenRouter 吊销 | 本机不能改 jim-server |

## 手动建特征

### 入口

- 时间线最后一个步骤后面一个「＋」（零件里；装配里没有时间线，照旧用左栏的 ＋ 加零件）。空零件时视口中间也有「新建草图」。
- 「＋」打开分组菜单，图标和工具图鉴一致（`OpIcon`）：
  - 草图
  - 加料：拉伸、旋转、放样
  - 切除：拉伸切除、孔
  - 修饰：圆角、倒角、抽壳、拔模
  - 复制：线性阵列、圆周阵列、镜像
- 前提不满足的置灰，写出原因：「先画一个草图」「至少要两个草图」「还没有实体」「先做一个加料、切除或孔」。

### 表单

表单放在右侧面板上的详情层（步骤面板的位置），从上到下：类型和名字（可以改名、写设计意图）、字段、底栏（取消 · 完成）。字段由每种特征的字段表（`app/src/studio/feature-forms.ts`）生成：

| 字段类型 | 用在 | 怎么填 |
| --- | --- | --- |
| 数值 | 距离、半径、个数…… | 数字或表达式（`L/2`、参数名），出错时就地写原因 |
| 选项、开关 | 方向、加料 / 切除、轴、贯穿 | 分段按钮、开关 |
| 草图 | 拉伸、旋转 | 下拉，列出这一步之前的草图，缺省是最近一个还没被用过的 |
| 草图列表 | 放样 | 按顺序勾选，可以上下调 |
| 特征列表 | 阵列、镜像 | 勾选这一步之前的加料、切除、孔 |
| 面 / 边 | 圆角、倒角、抽壳、拔模、孔口、草图贴面 | 选择框：激活后视图退回这一步之前的实体，单击加入或移出，内核合成语义条件（`selectorFor`），框里写成白话（`selector-words.ts`）；合成不出来时说明「少选几个，或者分成两步」 |
| 平面 | 草图、孔 | 基准面（上视 / 前视 / 右视）+ 偏移 + 倾斜（轴、角度），或「贴在一个面上」（面选择框） |
| 图形列表 | 草图 | 每个图形一行：类型、尺寸、中心、挖掉；折线是点表（x, y），可以加删行 |
| 点列表 | 孔中心 | 同上 |

每种特征的缺省值（打开就能建出来的，选择类的除外）：

| 特征 | 缺省 |
| --- | --- |
| 草图 | 没有实体时在上视基准面上画 40×30 的矩形；有实体时贴在最上面的平面上，画 ⌀10 的圆 |
| 拉伸 | 最近一个没用过的草图，距离 10；「拉伸切除」是切除、贯穿 |
| 旋转 | 最近一个没用过的草图，绕 Z 轴 360° |
| 放样 | 最近的两个草图 |
| 孔 | 贴在最上面的平面上，孔心 (0, 0)，⌀5，贯穿 |
| 圆角 / 倒角 | 先选边；R2 / 1 |
| 抽壳 | 开口是最上面的面，壁厚 2 |
| 拔模 | 先选面；3°，中性面是上视基准面 |
| 线性阵列 | 最近一个加料、切除或孔；沿 +X，3 个，间距 10 |
| 圆周阵列 | 同上；绕 Z 轴 6 个 |
| 镜像 | 同上；关于右视基准面 |

id 自动取第一个没用过的（`fillet2`），名字留空，显示为「圆角2」（`displayName`）。

### 实时重建和撤销

- 表单里每次改动（防抖 300 ms）调用 `studio.editTree(change, { group })`：第一次是插入，之后是替换这个特征。`group` 在打开表单时生成，一张表单一个。
- 引擎 `set_tree` 带 `group` 时（`engine.ts` 的 `adopt`）：撤销栈顶的条目也是这个 `group`，就只换掉当前的树、更新这一步的说明，不再压新的条目；否则照常压一条并记下 `group`。所以整张表单是一步撤销，撤销回到打开表单之前。
- 「取消」：这张表单写进去过，就撤销一次；否则直接关掉。「完成」或 Esc：关掉表单，视图停在这一步。
- 重建失败（圆角太大）时，时间线上这一步照常标红，表单顶上写失败原因，可以接着改。
- 桌面版的 agent 正在改模型时表单不能写（沿用 `busy`）；`set_tree` 的 `base_rev` 照旧防止覆盖 agent 刚做的改动。

### 步骤面板

- 加「编辑」（有表单的特征）和「上移一步」「下移一步」，和「删除」放在一起。
- 网页上原来交给助教的入口改成手动的：「让助教改这一步」→「编辑」；「让助教来选」→ 选择框里的说明；核对不满足时的「让助教修正」去掉。桌面版的「给 agent 留备注」不变。

## 验收

1. 空项目里只用界面：画 60×40 的矩形、拉伸 20、打 ⌀16 的孔，「带孔的垫块」练习的要求全部打勾（e2e）。
2. 「竖边圆角，顶边倒角」：在模型上点四条竖边建圆角、点顶面建倒角，练习完成（e2e）。「把盒子的特征顺序改对」：把外圆角上移一步，练习完成（e2e）。
3. 每个练习的参考答案里的每个特征，都能用表单表达：它的类型有表单，它用到的字段表单里都有（单元测试）。
4. 表单里改一个数，视图跟着变；整张表单只占一步撤销；「取消」以后特征树和打开表单之前一模一样（单元测试 + e2e）。
5. 桌面版窗口里同样能新建、编辑、上移下移；agent 下一次调用的结果开头写着人做的改动（截图核对 + 引擎单元测试）。
6. 网页不再请求 `/api`，构建产物里没有对话和分享的代码；打开工作台后 localStorage 里没有 `ft-studio-deepseek-key` 和对话记录。
7. `npm run check`、`npm run build`、`npm run e2e` 全绿，e2e 不再起 API 服务；部署流程不再碰 API。

## 落地记录（2026-11-22）

- **按方案做了**：表单（`app/src/studio/ui/feature-form.tsx`）和它的规则（`app/src/studio/feature-forms.ts`），时间线的「＋」和步骤面板的「编辑」「上移一步」「下移一步」，网页和桌面版共用；引擎的 `edit_tree`（带 `group`）；网页去掉对话、分享、自填 key、标注和整个 `app/server`；练习卡在右侧面板顶上，「看参考做法」；部署流程和 Playwright 不再起 API；`app/scripts/retire-api.sh`；文档。
- **比方案多做的**：
  - D14 取消写回原样、D15 拉伸要新草图（见上表）。
  - 表单开着时换零件：时间线随零件重新挂载，表单关掉；`editTree` 拒绝为已经不在显示的零件写入。别处改了这个特征（模型上的尺寸、agent、撤销），表单跟着显示；特征没了，表单关掉。
  - 参数面板最后一行「＋ 新参数」：没有助教以后，人要自己能建参数（原来只能在模型上的尺寸标签里「设为参数」）。
  - 参考做法的零件上方有「回到练习」。
  - 内核：一步之后什么都不剩（切除切掉整个实体）、或者实体量不了（绕不在草图平面里的轴旋转）时，原来整次重建抛 OCCT 异常、页面上什么都不显示，现在算成这一步的错误；旋转的提示补了「轴要在草图平面里」。手动建模很容易做出这两种步骤。
  - 网页上「核对没通过」不再有交给谁的按钮；步骤的选择合成不出描述时，说明「少选几个，或者分成两步」。
- **和方案不同的**：
  - 放样的截面按特征树里的顺序连，不能在表单里上下调（实际的放样几乎都是这个顺序）。
  - 空零件的「新建草图」放在右侧面板的「从一张草图开始」里，没有放在视口中间。练习的空零件只有「从草图开始」一个按钮。
  - 验收 2 的 e2e 做了倒角（点顶面选一圈边）和调顺序；圆角选四条竖边要在画布上点准每条边，e2e 没做，由单元测试保证「＋ 圆角」的缺省值和练习答案都能用表单表达。
