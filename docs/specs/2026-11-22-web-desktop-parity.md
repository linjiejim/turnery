# 网页工作台补齐桌面版的能力

- 状态：已实现（2026-11-22，待合并）；和方案不同的地方见文末「落地记录」
- 日期：2026-11-22
- 范围：网页工作台（`/studio`）能做桌面版 Turnery 能做的建模：一个项目里多个零件、装配、共享参数、STEP 参考件、标准件、螺纹，3MF 和零件清单导出；「直接做」的助手拿到和桌面版内置助手一样的命令。
- 不在范围：社区和作品发布（另议，见 PR #62 的讨论）；接本机的 Claude Code / Codex（MCP），读写电脑上的文件夹；给外部 agent 的备注、动态列表、agent 请你点选（`request_pick`）、agent 指给你看（`show`）；多个标签页同时改同一个项目；装配的缓存预览和零件并行准备（桌面版的 `component-pool`）。
- 相关：`app/src/desktop/core/engine.ts`（引擎）、`app/src/desktop/use-desktop.ts`（引擎到 `Studio` 的适配）、`app/src/desktop/ui/parts-sidebar.tsx`、`app/src/studio/worker.ts`、`app/src/routes/studio.tsx`、`docs/specs/2026-11-07-arbor-desktop.md`

## 为什么

桌面版和网页共用特征树、内核和视口组件，但网页只有一个零件：`use-studio.ts` 自己存一棵树、自己管撤销，装配、STEP、共享参数、标准件都只在桌面版的引擎里。PR #62 想在 `use-studio` 上一块块补，结果是第二套项目逻辑，和桌面版各走各的。

桌面版的引擎本来就不绑平台：文件系统和内核都从外面传进来（`Files`、`KernelHost`），同一份代码已经跑在 Electron 主进程、CLI 和单元测试里。网页再给它一套浏览器里的文件系统和内核，就是第三个宿主。以后桌面版加的能力，网页自动有。

## 已定

| 问题 | 决定 | 理由 |
| --- | --- | --- |
| 网页怎么得到桌面版的能力 | 引擎跑在页面里：`BrowserFiles`（IndexedDB）+ `WorkerKernelHost`（现有的内核 Worker），窗口这一侧复用桌面版的 `useEngine` / `useDesktopStudio` 和左栏组件 | 一套引擎三个宿主，不再写第二套项目逻辑 |
| 文件存哪 | 浏览器的 IndexedDB，虚拟路径 `/web/projects/<项目名>/…`。存不了（隐私模式、配额）时退回内存，页面上说清楚关掉就没了 | 不上传服务器；和桌面版一样「文件就是真相」 |
| 原来那一个模型 | 第一次打开时搬进项目「我的模型」，文件 `零件.turnery.json`；`localStorage` 里的旧数据留着不删 | 学习者不丢东西；万一出错还能找回 |
| 项目 | 一个项目一个文件夹。新建时选「单个零件」或「多个零件（装配）」；装配项目和桌面版一样建 `<名字>.turnery-asm.json` 和共享参数文件 | 和桌面版 `open_project create` 一致 |
| 内核 | 一个 Worker 一个内核，不分槽；切零件就重建。堆超过 1400 MB 时换一个 Worker，并把文件、组件、上下文和树重新交过去 | 网页的零件小，先求对；分槽和并行准备是性能优化，以后按需要加 |
| 撤销 | 用引擎的撤销 / 重做（每个文件 100 步）。刷新页面后撤销历史清空 | 原来存在 `localStorage` 的 30 步只对一个零件有意义；多文件以后由引擎统一管 |
| 「直接做」的助手 | 工具和系统提示词换成桌面版内置助手的（`catalog.ts` 的命令和 `AGENT_GUIDE`），去掉网页上做不了的：`guide`、`request_pick`、`show`、`get_notes`、`resolve_note`。工具在浏览器里由引擎执行，发消息时附上 `get_state` 的文字 | 和桌面版内置助手同一套命令，桌面版已经用同一个模型（DeepSeek）跑通；工具描述的总长度和网页原来的差不多 |
| 「边做边学」 | 工具和提示词不变，执行改由引擎来做（命令同名） | 课程和练习的评测不受影响 |
| 练习固定的要求 | 每次改动后检查，被改掉就放回去，结果里说明（和原来一样，换成在引擎外面做） | 行为不变 |
| 「新建零件」按钮 | 去掉顶栏那个「清空并新建」。新建零件、新建装配、新建项目、导入都在左栏的「＋」和顶栏的项目菜单里，新零件是项目里的一个新文件，不清空任何东西 | 有了项目以后，「清空」不再是新建的意思；不丢东西也就不用确认 |
| 导入 | 「导入文件…」和拖进视图：`.turnery.json` / `.json`（特征树）、`.turnery-asm.json`、`.params.json`、`.step` / `.stp` 加进当前项目；`.zip` 当作项目包，新建一个项目。导入的零件直接打开，提示里能撤销（删掉这个文件） | 不再替换当前模型，原来的零件留着 |
| 导出 | STEP / STL / 3MF / build123d 代码 / 特征树 JSON / 零件清单（装配）/ 整个项目（zip）。都走引擎的 `export`，写到不在项目里的临时文件夹，读出来下载后删掉 | 和桌面版导出的内容一模一样 |
| 分享链接 | 只分享单个零件，装配时按钮不可用并说明原因（导出项目包发给别人） | 分享快照的格式是一棵树；装配分享另议 |
| 左栏 | 复用桌面版的 `PartsSidebar`：文件、结构（装配零件，可以隐藏、隔离、改颜色、改名、打开、在装配里改）、「＋ 零件」。网页的顶部是项目菜单，文件行多一个 ⋯（改名、删除）。≥ 1024 默认展开，记住开合；窄屏收起，用顶栏的项目菜单切换文件 | 和桌面版长得一样，学会一个就会另一个 |
| 删除文件、删除项目 | 删文件立刻执行，提示里能撤销；删项目要确认（不能撤销） | jim-uiux：可撤销的不问，不可撤销的才问 |
| 对话 | 每个项目一段对话，切项目就换成那个项目的对话 | 一个项目的对话不该带进另一个 |

## 交互

- 顶栏：返回 · 左栏开关 · 「项目名 ▾ / 装配 / 零件」· 撤销 · 重做 · 导出 ▾ · 分享 · ⋯。点项目名弹出项目菜单：切换项目、新建零件、新建装配、新建项目…、导入文件…、导出整个项目、重命名项目…、删除项目…。
- 左栏顶部：项目名 ▾（同一个菜单）、搜索、＋（新建零件 / 新建装配 / 导入文件…）。
- 空装配：结构区写「还没有零件：点上面的 ＋ 加一个」，＋ 里是「新零件… / 已有零件或装配… / STEP 参考件…」，和桌面版一样。选「已有零件」和「STEP」弹出项目里的文件，也能「从电脑上传…」。
- 加载：内核下载有进度；打开大装配时视口上方显示正在加载哪个文件。

## 验收

1. 新建装配项目，用「＋ 零件」加两个新零件和一个 STEP，视口里看到三个零件，结构区能隐藏、隔离、改颜色；点一个零件「在装配里改」，周围的零件半透明显示。
2. 两个零件用共享参数文件，改一个共享参数，两个零件都跟着变。
3. 「直接做」让助手建一个带螺纹和 M3 标准螺钉的装配，工具在浏览器里执行成功（脚本模型的 e2e 覆盖工具链路）。
4. 导出 STEP / STL / 3MF / 零件清单 / 项目 zip；把导出的 zip 再导入，得到一样的项目。
5. 旧版的一个模型第一次打开时出现在「我的模型」里；刷新后项目和文件都在。
6. 原有的工作台 e2e（对话、标注、测量、剖视、分享、工程图、练习等）全部通过；改了行为的（新建、导入）按新行为改测试。
7. `npm run check`、`npm run build`、`npm run e2e` 全绿。

## 落地记录（2026-11-22）

- **按方案做了**：引擎跑在页面里（`app/src/studio/web-host/`），桌面版的 `useEngine`、`useDesktopStudio`、`PartsSidebar`、`AddPartMenu` 通过 `installBridge` 原样复用；项目、导入导出、旧模型迁移、每个项目一段对话、「直接做」换成桌面版内置助手的命令（`app/src/studio/web-agent.ts`）。
- **为此改了共用代码**：
  - `catalog.ts` 的命令可以按语言生成（`commandsIn`、`guideIn`、`agentCommandsIn`），网站服务端按每个请求的语言给工具；原来的 `COMMANDS` / `AGENT_GUIDE` 不变。这一处大部分是缩进，`git diff -w` 只有几行。
  - `PartsSidebar` 加了 `head`、`tools`、`filesHint`、`onDeleteFile` 四个可选参数，桌面版不传，行为不变。
  - 内核 Worker 的协议加了 `setAssets`、`setComponents`、`setContext`、`restyle`、`looks`；`KernelClient` 换 Worker 时把这些重新交过去。
  - 内核在没拿到文件时的报错不再说「只能在桌面版里用」，改成「要在项目里打开」。
- **比方案多做的**：
  - 另一个标签页也开着工作台时，顶上说明「两边各存各的」（`BroadcastChannel`）。
  - 装配打开时，对话的示例换成装配的；「边做边学」下提示放零件要用「直接做」，一键切换。
  - 窄屏收起左栏后，顶栏的项目菜单里列出项目的文件，可以切换。
- **和方案不同的**：
  - 练习：练习的起始模型放进当前的空零件，否则新建一个零件；固定的要求只在练习的那个零件里生效。练习进行中导入特征树，换掉的是练习零件的内容（否则答案会进一个新零件，练习卡片就不见了）。
  - 从链接打开的示例（`?start=`）和对话里「打开示例模型」放进空零件时不再弹提示：要的东西已经在眼前了。
- **没做**：内核分槽和装配预览缓存（切文件就重建）；窄屏上的「结构」列表（窄屏仍可以在视图里点选零件、隐藏、隔离）。
