# Two languages: Chinese and English

English · 中文摘要见文末

Turnery's interface comes in Chinese and English. This page says how the language is chosen, how strings are written, and what is not translated yet.

## How the language is chosen

All of it is in [`app/src/lib/i18n.ts`](../app/src/lib/i18n.ts).

| Where | Language comes from |
| --- | --- |
| The website | The address. `/en/…` is English, everything else Chinese. The router runs with `/en` as its basename, so `<Link to="/learn">` stays in the language it is in. Having chosen English once, a bare address takes you to its `/en` twin. |
| The desktop window | The choice in the title bar's language menu, else the system language (Chinese for `zh-*`, English otherwise). The window tells the main process, so the menu bar, file dialogs and update notices follow it (`desktop/src/main/lang.ts`, `tm("文件", "File")`). |
| Node: unit tests, the build, the engine | `TURNERY_LANG=en`, else Chinese. Tests run in Chinese. |

The language is fixed for the life of a page: switching stores the choice and reloads. So tables built when a module loads (`const NAV = [{ label: t(…) }]`) can use `t()` like everything else.

The build prerenders an English copy of each top-level page under `dist/en/` with English titles and descriptions and `hreflang` links between the two (`app/scripts/prerender.mjs`, `app/src/lib/page-meta.ts`). Lesson, card and teardown pages are prerendered in Chinese only; their English addresses fall back to the app as any other route does.

## Writing a string

Write both languages where the string is used:

```tsx
import { t, byLocale } from "@/lib/i18n"

<Button>{t("回到最新", "Back to latest")}</Button>
notify(t(`已删除「${name}」`, `Deleted “${name}”`))
const tips = byLocale(["…", "…"], ["…", "…"])   // any value, not only strings
```

- The Chinese stays exactly as it was: unit and e2e tests match it.
- English: sentence case, short sentences, verbs on buttons, no "Please", US spelling, “curly quotes” where Chinese uses 「」.
- A guard in `npm run check` (`app/src/tests/unit/i18n.test.ts`) fails when the English half of a `t("…", "…")` pair still has Chinese characters in it.
- Kinds of feature on screen: `opLabel(op)` (from `studio/dsl.ts`). `OP_NAMES` stays Chinese, because the kernel and the agent's messages use it.
- A helper whose text goes both on screen and to a model takes a `shown` flag (`selectorWords(…, true)`, `lookText(…, true)`): only the on-screen call gets English.

## What is not translated yet

| What | Why it is still Chinese |
| --- | --- |
| What the agent reads: the MCP guide, tool descriptions, kernel and engine messages, the tutor's and assistant's system prompts | Models read Chinese well, and these texts are long and precise. In English the tutor and the built-in assistant get one extra rule (`ENGLISH_REPLIES` in `studio/prompt.ts`): answer, and name features, in English. |
| Lesson and card bodies (`app/src/content/lessons`, `app/src/content/cards`), teardown step text | About 50k characters of teaching text that needs a careful translation and review of its own. English pages show a notice (`components/zh-only.tsx`). |
| The `turnery` command line's own output | It is mostly read by agents. |
| Names written by the agent or by you (features, parameters, notes) | They are your content. |

The course catalog is translated: curriculum, lesson titles and summaries, the command atlas and the glossary live in `app/src/content/en/` and are merged over the Chinese data when the page is English. Anything missing there falls back to Chinese.

## 中文摘要

界面有中文和英文两版。网站按地址决定语言（`/en/…` 是英文），桌面版按标题栏的语言菜单或系统语言，菜单栏和对话框跟着窗口走。界面上的每一句写成 `t("中文", "English")` 一对，中文保持原样。给 agent 和模型看的文字、课程正文、命令行的输出暂时只有中文；课程目录（大纲、课名、图鉴、术语）的英文在 `app/src/content/en/`。
