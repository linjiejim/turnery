# Two languages: Chinese and English

English · 中文摘要见文末

Turnery comes in Chinese and English: the interface, the course, and what the agent reads. This page says how the language is chosen, how strings are written, and what is not translated.

## How the language is chosen

All of it is in [`app/src/lib/i18n.ts`](../app/src/lib/i18n.ts).

| Where | Language comes from |
| --- | --- |
| The website | The address. `/en/…` is English, everything else Chinese. The router runs with `/en` as its basename, so `<Link to="/learn">` stays in the language it is in. Having chosen English once, a bare address takes you to its `/en` twin. |
| The desktop window | The choice in the title bar's language menu, else the system language (Chinese for `zh-*`, English otherwise). The window tells the main process, so the menu bar, file dialogs and update notices follow it (`desktop/src/main/lang.ts`, `tm("文件", "File")`). |
| Node: unit tests, the build, the engine | `TURNERY_LANG=en`, else Chinese. Tests run in Chinese. |

The language is fixed for the life of a page: switching stores the choice and reloads. So tables built when a module loads (`const NAV = [{ label: t(…) }]`) can use `t()` like everything else.

The build prerenders an English twin of every page under `dist/en/`, with English titles and descriptions and `hreflang` links between the two (`app/scripts/prerender.mjs`, `app/src/lib/page-meta.ts`). Lessons, cards and teardowns get their English titles from the catalog, and their descriptions say the text itself is in Chinese.

## Writing a string

Write both languages where the string is used:

```tsx
import { t, byLocale } from "@/lib/i18n"

<Button>{t("回到最新", "Back to latest")}</Button>
notify(t(`已删除「${name}」`, `Deleted “${name}”`))
const tips = byLocale(["…", "…"], ["…", "…"])   // any value, not only strings
```

- The Chinese stays exactly as it was: unit and e2e tests match it.
- English: sentence case, short sentences, verbs on buttons, no "Please", US spelling, “curly quotes” where Chinese uses 「」.
- A guard in `npm run check` (`app/src/tests/unit/i18n.test.ts`) fails when the English half of a `t("…", "…")` pair still has Chinese characters in it.
- The kit's own copy (`components/ui/`, from jim-uiux) is Chinese in `lib/strings.ts`, kept as upstream ships it; its English is the table in `lib/kit-strings.ts`, swapped in at boot. A kit upgrade that adds a key fails the type check until the key has its English there.
- Kinds of feature on screen: `opLabel(op)` (from `studio/dsl.ts`). `OP_NAMES` stays Chinese, because the kernel and the agent's messages use it.
- A helper whose text goes both on screen and to a model takes a `shown` flag (`selectorWords(…, true)`, `lookText(…, true)`): the on-screen call follows the page (`t()`), the other follows the agent (`ta()`, below).

## What the agent reads

The MCP guide, tool and parameter descriptions, tool results, kernel and engine messages, and the built-in assistant's system prompt are written in both languages with `ta("中文", "English")` from [`app/src/lib/agent-lang.ts`](../app/src/lib/agent-lang.ts). `ta()` follows the *agent's* language, which is not always the page's:

| Where | The agent's language |
| --- | --- |
| `turnery mcp`, the `turnery` CLI, the app's main process | Settled at start by `desktop/src/lang-boot.ts`: `TURNERY_LANG` if set, else the window's last choice (saved as `lang` in `~/.turnery/settings.json`), else the system language. Kernel threads get it with each request. In the app it also changes live when the window's language changes; an MCP session started before that keeps its guide and descriptions until the agent restarts it. |
| The browser workbench | The page's language; its kernel worker gets it through the worker's name. |

Rules for this text:

- No `ta()` in module-level constants in code that runs in the app's main process or the kernel: make the text when it is used. (Tool schemas and the guide are the exception: they are read where the language is settled before any module loads.)
- Output that code parses keeps its structure in both languages: the ✓ ✗ ⚠ ? prefixes, line layout, and phrases other code matches (those matchers accept both languages, e.g. `/^✗ (模型已经是|The model is already at version )/`).
- `OP_NAMES` and names like 「拉伸1」, and the part key 「主体」, stay as they are: files, mates and checks refer to them.
- `src/tests/unit/agent-lang.test.ts` runs a whole modeling session in English and in Chinese; `agent-budget.test.ts` keeps the English tool list under its budget and free of Chinese.

## What is not translated

| What | Why |
| --- | --- |
| Names written by the agent or by you (features, parameters, notes) | They are your content. |
| Titles of the Chinese help pages a card cites as its sources | They name the page they link to; an English edition of the page would need its own link. |

The course is translated:

- Lessons and cards (`app/src/content/lessons`, `app/src/content/cards`) carry both languages in place: `t()` for strings, `byLocale(<>…</>, <>…</>)` for rich text, and `byLocale([...], [...])` for quiz options, which must keep the same order and length (answers are indexes).
- The catalog (curriculum, lesson titles and summaries, the command atlas, the glossary) lives in `app/src/content/en/` and is merged over the Chinese data when the page is English. Anything missing there falls back to Chinese.
- Teardowns come from baked models, so their English is an overlay too (`app/src/content/en/teardown-text.ts`, applied in `loadManifest`), checked against every baked manifest by `src/tests/unit/i18n-teardowns.test.ts`. A model re-baked with new text needs its English added there.

## 中文摘要

界面、课程和给 agent 看的文字都有中文和英文两版。网站按地址决定语言（`/en/…` 是英文），桌面版按标题栏的语言菜单或系统语言，菜单栏和对话框跟着窗口走。界面上的每一句写成 `t("中文", "English")`；给 agent 看的写成 `ta("中文", "English")`，跟随 agent 的语言：`turnery mcp` 和命令行启动时按 `TURNERY_LANG`、窗口上次的选择（`~/.turnery/settings.json`）、系统语言依次决定。中文保持原样。
